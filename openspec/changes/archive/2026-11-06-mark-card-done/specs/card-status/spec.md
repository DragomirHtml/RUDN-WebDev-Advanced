## Purpose

Позволяет пользователю отмечать карточки Kanban-доски как выполненные и возвращать их обратно. Состояние сохраняется на сервере и переживает обновление страницы.

## ADDED Requirements

### Requirement: На карточке есть элемент управления отметкой выполнения

Каждая отображаемая карточка на доске SHALL содержать видимый элемент управления для переключения состояния «выполнено» (например, чекбокс или кнопка).

#### Scenario: Элемент управления виден на карточке

- **WHEN** пользователь открывает доску с карточками
- **THEN** на каждой карточке отображается элемент управления для переключения статуса выполнения

#### Scenario: Элемент управления отражает текущее состояние

- **WHEN** пользователь открывает доску с карточками
- **THEN** элемент управления на каждой карточке показывает, выполнена она или нет (например, отмечен чекбокс для выполненных)

### Requirement: Отметка сохраняется на сервере

При переключении отметки выполнения система SHALL отправляет запрос на сервер и сохраняет состояние.

#### Scenario: Отметка сохраняется после переключения

- **WHEN** пользователь переключает элемент управления отметкой выполнения на карточке
- **THEN** система отправляет PATCH-запрос на сервер с `id` карточки и новым значением `isDone`

#### Scenario: Состояние переживает обновление страницы

- **WHEN** пользователь обновляет страницу (F5) после установки отметки
- **THEN** карточка остаётся в том же состоянии (выполнена или нет) — состояние загружается с сервера

### Requirement: Сервер принимает изменение отдельным эндпоинтом

Сервер SHALL предоставляет отдельный эндпоинт для изменения отметки выполнения конкретной карточки.

#### Scenario: PATCH-запрос меняет isDone

- **WHEN** сервер получает `PATCH /cards/:id` с телом `{ "isDone": true }` или `{ "isDone": false }`
- **THEN** сервер обновляет поле `isDone` у карточки с указанным `id` и возвращает обновлённую карточку

#### Scenario: Запрос без тела или с пустым телом

- **WHEN** сервер получает `PATCH /cards/:id` без тела запроса
- **THEN** сервер возвращает `400 Bad Request`

### Requirement: Валидация isDone в промежуточной функции

Запрос с негодным значением `isDone` SHALL отклоняется промежуточной функцией (middleware) с кодом `400`.

#### Scenario: isDone равно true — валидно

- **WHEN** middleware проверяет тело запроса `{ "isDone": true }`
- **THEN** запрос проходит валидацию и передаётся контроллеру

#### Scenario: isDone равно false — валидно

- **WHEN** middleware проверяет тело запроса `{ "isDone": false }`
- **THEN** запрос проходит валидацию и передаётся контроллеру

#### Scenario: isDone не булево значение — отклоняется

- **WHEN** middleware проверяет тело запроса `{ "isDone": "true" }` или `{ "isDone": 1 }`
- **THEN** middleware возвращает `400 Bad Request` без передачи запроса контроллеру

#### Scenario: isDone отсутствует в теле — отклоняется

- **WHEN** middleware проверяет тело запроса без поля `isDone`
- **THEN** middleware возвращает `400 Bad Request` без передачи запроса контроллеру

### Requirement: Контроллер возвращает 404 для несуществующей карточки

При попытке изменить отметку несуществующей карточки контроллер SHALL возвращает `404 Not Found`.

#### Scenario: Изменение отметки несуществующей карточки

- **WHEN** контроллер получает запрос для `id`, которого нет в списке карточек
- **THEN** сервис возвращает `null`, контроллер проверяет результат и возвращает `404 Not Found`

#### Scenario: Изменение отметки существующей карточки

- **WHEN** контроллер получает запрос для существующего `id`
- **THEN** сервис обновляет `isDone`, возвращает обновлённый объект Card, контроллер проверяет результат и возвращает `200 OK`

### Requirement: Сервис не зависит от HTTP

Функция сервиса `toggleCardDone` SHALL не содержать `req`, `res` и HTTP-статус-кодов.

#### Scenario: Сервис возвращает обновлённый объект или null

- **WHEN** контроллер вызывает `toggleCardDone(id, isDone)` для существующей карточки
- **THEN** сервис возвращает обновлённый объект Card с новым значением `isDone`

- **WHEN** контроллер вызывает `toggleCardDone(id, isDone)` для несуществующей карточки
- **THEN** сервис возвращает `null`, контроллер проверяет результат и самостоятельно решает: `200 OK` или `404 Not Found`
